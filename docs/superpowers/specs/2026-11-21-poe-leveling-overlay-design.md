# PoE 練等輔助 Overlay 設計

日期：2026-11-21

## 目的與原因
使用者練等時照一份攻略走（PoE1 3.29「靈體投擲轉充能打擊」暴徒速刷拓荒，Google 試算表，A1–A10，約 140 列，繁中）。
希望遊戲內有一個疊層，隨時顯示「現在該做什麼」，不必切出遊戲看表格。
資源消耗要小，不能影響遊戲效能（使用者明確要求）。

## 目標
- 透明、置頂、可點擊穿透的疊層視窗，顯示目前章節與當前步驟，以及該步驟的 TIPS。
- 進入新區域時自動跳到對應步驟（讀 PoE 的 `Client.txt`）。
- 區域內的步驟用快捷鍵手動前進／後退。
- 快捷鍵顯示／隱藏疊層。
- 攻略資料是獨立 JSON，之後換攻略只需換資料。
- 提供「選擇 JSON 檔」功能（檔案選擇對話框），可載入並切換其他攻略；上次選的檔案記在設定檔，下次啟動自動載入。載入時驗證格式，錯誤時顯示原因並保留目前攻略。

## 非目標
- 不讀取或修改遊戲記憶體，不注入遊戲，不做封包處理。
- 不自動判斷「王是否打死」「是否拿到寶石」。
- 不做查價、背包、天賦樹等其他功能。
- 不支援 PoE2。
- 第一版不做攻略編輯器，也不做試算表／CSV／網頁轉 JSON 的轉換工具（別的攻略需自行整理成同格式 JSON；之後可另議）。

## 反目標（做到了也算失敗）
- 吃掉可感知的 CPU／記憶體／GPU。
- 搶走遊戲的焦點或鍵盤輸入。
- 被遊戲視為違規工具（只讀日誌檔屬社群常見做法，但上線前仍須自行確認 GGG 政策）。

## 限制
- Windows 10，遊戲須為視窗化或無邊框視窗化，全螢幕獨占模式下疊層不會顯示。
- 開發者機器需要 Rust 工具鏈與 WebView2（待確認是否已安裝）。
- `Client.txt` 路徑依 Steam／台服而異，必須可設定。
- 攻略內容來自第三方，公開發布前應先徵得作者同意。

## 做法比較
| 做法 | 取捨 |
|---|---|
| Electron | 好調 UI，但體積與記憶體大（內含 Chromium），違反資源要求 |
| AutoHotkey | 輕量，但 GUI 弱、資料格式難擴充 |
| **Tauri（採用）** | 使用系統 WebView2，體積與記憶體小，前端仍是網頁技術；需裝 Rust |

使用者選擇 Tauri，理由是資源消耗小、不影響遊戲。

## 設計
三個部分：

1. **攻略資料（JSON）**
   試算表轉成結構：章節 → 步驟清單。每個步驟含：文字、TIPS（可空）、可選的 `zone`（觸發區域名稱）。
   攻略沒有逐步標區域，`zone` 需人工對照標註，這是最花工的部分。第一版可先只標每章的關鍵區域。
2. **日誌監看（Rust 後端）**
   追蹤 `Client.txt` 檔尾新增行，比對進入區域的訊息，找到對應 `zone` 的第一個步驟並通知前端。
   只讀檔尾增量，不全檔掃描，以降低資源消耗。
3. **疊層視窗（前端）**
   透明、置頂、點擊穿透；顯示章節、當前步驟與下一步預覽、TIPS。
   全域快捷鍵：下一步、上一步、顯示／隱藏。
   設定（日誌路徑、位置、透明度）存本機設定檔。

## 交給建造者決定
- 前端框架選擇（建議最簡：原生 HTML/TS，不加框架）。
- 區域訊息的實際比對字串（繁中客戶端格式需實測）。
- 快捷鍵預設值。
- 試算表轉 JSON 的方式（手動整理或寫一次性腳本）。

## 風險
- 全域快捷鍵與遊戲內快捷鍵衝突。
- 繁中客戶端日誌格式與英文不同，需用真實日誌驗證。
- 攻略著作權與 GGG 工具政策。
